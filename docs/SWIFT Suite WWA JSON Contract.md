# SWIFT Suite WWA JSON Contract

Recommended repo path: `docs/contracts/swpc_wwa_product_contract.md`

## Purpose

This contract defines the authoritative JSON structure for SWPC Watches, Warnings, Advisories, Alerts, Statements, Notices, Outlooks, and Summaries within the SWIFT suite.

The goal is to create one authoritative product object that can support:

* Official plain-language text products
* SWPC website rendering
* Partner email briefings
* Social media graphics
* Event timelines
* Sector-specific filtering
* Audit/history/replay during exercises or real events

The product object should be generated by the issuing application, such as the Geomagnetic Forecast Console, Geomagnetic Observations Monitor, Radiation Monitor, Solar Activity Console, or Partner Briefing Generator.

## Design Principles

1. One product object should describe one issued product.
2. The product JSON is the source of truth.
3. The text product, website card, briefing, and social media graphic should be generated from the same product object.
4. Product types should be consistent across the SWIFT suite.
5. Timing should be UTC-first.
6. Products should support probabilistic messaging without requiring exact probabilities in every display format.
7. The schema should be structured enough for automation but readable enough for forecasters and developers.

## Product-Specific Requirements

### Outlook

Must include:

* `sections` with planning periods such as Day One, Days Two Through Three, Days Four Through Seven
* `timing.time_basis = "UTC"`
* `rendering.social_media.template = "outlook_standard_v1"`

### Statement

Must include:

* `sections` describing what is under analysis, changing, or ending
* `confidence` when applicable
* `rendering.social_media.template = "statement_standard_v1"`

### Watch

Use when G3 or greater potential is credible but not yet warning-level.

Must include:

* `probabilities`
* `confidence`
* `timing.arrival_window`
* `update_policy`
* `rendering.social_media.template = "watch_standard_v1"`

### Advisory

Use for lower-level or lingering impacts, generally below warning-level concern.

Must include:

* `confidence`
* `impacts`
* `update_policy`
* `rendering.social_media.template = "advisory_standard_v1"`

### Warning

Use when significant impacts are expected, imminent, or ongoing.

Must include:

* `confidence`
* `probabilities` when available
* `impacts`
* `update_policy`
* `rendering.social_media.template = "warning_standard_v1"`

### Observed Alert

Must include:

```json
"observations": {
  "observed_time_utc": "datetime",
  "observation_period_utc": {
    "start": "datetime",
    "end": "datetime"
  },
  "observed_condition": "G5",
  "basis": "string",
  "network": "official_kp_network",
  "stations_included": []
}
```

Use:

```json
"rendering.social_media.template": "observed_alert_standard_v1"
```

### Notice

Must include:

```json
"service_status": {
  "status_type": "data_availability",
  "affected_systems": [],
  "status": "degraded",
  "effect_on_forecast": "string",
  "official_products_remain_valid": true
}
```

Use:

```json
"rendering.social_media.template": "notice_standard_v1"
```

### Summary

Must include:

* `sections` with Event Overview, Observed Conditions, Current Status
* `rendering.social_media.template = "summary_standard_v1"`

## Naming Convention

Product IDs should follow:

```text
YYYYMMDDTHHMMZ-SWPC-PRODUCTTYPE-EVENTKEY-SEQUENCE
```

Examples:

```text
20240508T0630Z-SWPC-STATEMENT-AR3664-001
20240508T2200Z-SWPC-ADVISORY-AR3664-001
20240509T1230Z-SWPC-WATCH-AR3664-002
20240509T1745Z-SWPC-WARNING-AR3664-001
20240510T2254Z-SWPC-ALERT-G5-AR3664-001
```

## Application Responsibilities

### Geomagnetic Forecast Console

Should generate:

* Space Weather Outlook
* Space Weather Watch
* Space Weather Advisory
* Space Weather Warning
* Warning Updates
* Forecast-related Statements

### Geomagnetic Observations Monitor

Should generate:

* Observed Space Weather Alerts
* observation basis fields
* station lists
* observed threshold metadata

### Partner Briefing Generator

Should consume WWA JSON and generate:

* partner email briefings
* social media graphics
* briefing graphics
* website cards
* event timelines

### Product Archive

Should store:

* JSON product object
* rendered official text
* rendered social graphic metadata
* timestamped product lifecycle

## Future Enhancements

### Direct Social Publishing

The Partner Briefing Generator may later support direct publishing of approved social media graphics to official channels such as X/Twitter and Facebook Pages. CAC/NOAA authentication should identify the SWIFT user, while platform access tokens should remain server-side. A future workflow should include review/approval status, exact post text, exported PNG asset, alt text, platform response IDs, and an immutable audit log. For the beta prototype, social media output is limited to exported PNG graphics and reviewed copy.
